# Supplementary Material

This site accompanies the paper with supporting datasets, curated evidence tables, ship-level risk scenarios, security requirements, and exploratory visual summaries. Open an artifact page to read the formatted notes and context, or use the Data File column to download the corresponding CSV for reuse, review, or independent analysis.

| Artifact Page | Data File | Notes |
|---|---|---|
| [Ship cyber-physical attack surface considered in this paper](./ship-cyber-physical-attack-surface.md) | [ship-cyber-physical-attack-surface.csv](./ship-cyber-physical-attack-surface.csv) | Maps ship domains, assets, data flows, and security relevance for the paper's cyber-physical system model. |
| [Examples of CVEs relevant to naval and maritime cyber-physical systems](./representative-maritime-cves.md) | [representative-maritime-cves.csv](./representative-maritime-cves.csv) | Representative product vulnerabilities used to connect CVE evidence with maritime attack-surface roles and potential impacts. |
| [Maritime-adjacent and infrastructure CVEs relevant to AIS, GPS, wireless access, radio, and supporting platforms](./maritime-adjacent-infrastructure-cves.md) | [maritime-adjacent-infrastructure-cves.csv](./maritime-adjacent-infrastructure-cves.csv) | Vulnerabilities in AIS/GPS parsers, wireless devices, radio infrastructure, and supporting platforms whose maritime relevance depends on deployment context. |
| [Maritime-native CVEs affecting navigation, SATCOM, and shipboard communication equipment](./maritime-native-cves.md) | [maritime-native-cves.csv](./maritime-native-cves.csv) | Direct shipboard, navigation, and SATCOM equipment vulnerabilities, including NavBox, FELCOM, Cobham, and satellite terminal families. |
| [Representative ship-level risk scenarios derived from CVE families](./representative-ship-level-risk-scenarios.md) | [representative-ship-level-risk-scenarios.csv](./representative-ship-level-risk-scenarios.csv) | Translates CVE families into ship-level scenarios such as reconnaissance, SATCOM-to-OT pivoting, navigation-data manipulation, forensic compromise, and persistent infrastructure access. |
| [Abstract attack paths combining CVE-enabled stages with AIS/ECDIS triggering](./abstract-attack-paths-ais-ecdis.md) | [abstract-attack-paths-ais-ecdis.csv](./abstract-attack-paths-ais-ecdis.csv) | Abstract paths showing how SATCOM footholds, gateways, parser flaws, and firmware persistence can combine with AIS/ECDIS-based cyber-physical triggering. |
| [Threat-model-driven security requirements for naval and maritime systems](./security-requirements-maritime-systems.md) | [security-requirements-maritime-systems.csv](./security-requirements-maritime-systems.csv) | Requirements derived from the threat model, covering navigation-data validation, VDR/log integrity, communication hardening, segmentation, stakeholder access, and operational resilience. |
| [Experimental Scenario Flow: Product Vulnerability Meets AIS/ECDIS Triggering](./experimental-scenario-flow.md) | [experimental-scenario-flow.csv](./experimental-scenario-flow.csv) | Illustrative AIS/ECDIS use case showing how insecure maintenance or firmware persistence, dormant behavior, navigation-data conditions, bridge response, and operational effects fit together. |
| [Maritime CVE Research Notes](./maritime-cve-research-notes.md) |  | Formatted notes from the CVE-gathering document |
| [Visual Explorations](./visual-explorations.md) |  | Visual summaries of the evidence-to-scenario logic, CVE relevance taxonomy, article framing choices, and generated CVE count charts. |

Blank Data File cells indicate pages that are narrative notes or visual summaries rather than standalone CSV tables.
